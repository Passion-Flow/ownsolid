# Identity audit-read integration draft (AUD-108)

Read SCI's exact five-file contract at e15269e221b949ea5091a6545cf0da489739ad47 before this draft. This draft concerns the real identity consumer only, not support collection or a replacement audit ledger. It is not a product implementation or acceptance record.

The current HTTP entry is Handler.listAuditEvents, invoked from the authenticated Admin dispatcher, with its server-generated request ID currently retained only in the outer dispatcher. Both its legacy representation and optional verified assistant representation reach Service.listForActor. That transaction rechecks the current session, optionally authorizes one workspace, reads a bounded allowlisted page, and returns only after transaction success. Insert the access record in that exact transaction; on append, cancellation or commit uncertainty return no page or assistant attribution.

Preserve existing public fields, filters, cursor domains, the installation-wide platform Admin view, the explicit installation-tenant workspace check, and assistant-attribution verification. The legacy installation-wide view deliberately includes events from other managed tenants; its existing native positive control asserts that behavior. Do not silently replace this contract with one workspace or a tenant query supplied by the browser.

Use a fixed proposed action audit.events_read, existing success outcome, the current server-rechecked human actor and Admin audience, and the existing HTTP request correlation. Do not log result rows, original reasons, email filters, raw query strings, driver errors, tokens, digests or protected configuration. Safe selection metadata can describe the resolved view kind, representation, bounded limit and returned count. Retrying a read has a fresh correlation and an independently appended event. Capture the page before appending, so the new access event does not appear inside its own response and distort cursor/lookahead semantics.

The existing writer binds installation/default workspace. It may describe the actual installation-wide view but must not pretend that workspace-specific reads were attributed to the selected workspace. SCI owns the real scoped append function and its grant/audit-chain contracts. Exact workspace integration needs that API with the consumer's verified workspace, actor and request ID. No unused injected helper is a substitute for the live consumer. New public payload/redaction behavior goes through DEV; Web owns the action name in both locales.

Existing allowlisted identity projections exclude audit metadata, identifier digests and arbitrary source columns. Retain intentionally visible operator reason and actor/subject fields under the current public contract; do not claim arbitrary sensitive-text redaction without an admitted policy. Sentinels in nonprojected metadata/digests and private failure details must remain absent from page, errors and access events.

Native HTTP acceptance needs ordinary and opt-in reads; server-generated correlation; real current actor; revoked/Portal/member/foreign-workspace refusals; tampered cursor and scope injection; no row/attribution on audit refusal, commit-not-forwarded or suppressed ACK; explicit retry readback; bounded concurrent reads; and unchanged cursor/assistant projections. Run through actual SQL/TLS, not a direct append helper. Preserve fixture-private schema ownership and exact raw outcomes.

No dependency, model or dataset is added. Existing Go BSD-3-Clause and PostgreSQL License notices apply. Primary guidance: https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html and https://troubleshoot.sh/docs/redact/redactors/ . Scope and exact acceptance remain open until source integration and execution.
