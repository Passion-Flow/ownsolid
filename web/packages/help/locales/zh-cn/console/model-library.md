# 模型库

[模型库](/library)保存切换器中所选工作空间的模型，并显示它们的导入情况。模型以模型包的形式导入，因此无需联网。

## 导入模型

1. 在联网机器上，按“目录”中显示的修订版本获取模型文件。
2. 打开[导入模型包](/library/import)，展开“如何制作模型包”。复制适合所用工具的命令，在该修订版本的文件所在目录中运行。
3. 把生成的 `bundle.tar` 带到能访问控制台的电脑上，选择这个文件。
4. 填写原因，接受模型的许可协议，然后选择“开始导入”。

上传期间可以继续使用控制台的其他页面。关闭标签页会停止上传：从“导入记录”打开这次导入，选择同一个文件，就会从服务器中断的位置继续。不同的文件在写入任何内容之前就会被拒绝。

发布模型前，服务器会将每个文件与其公布的哈希值核对。导入就绪后，选择“打开模型”可以查看已发布的模型记录。

## 制作模型包

在保存模型文件的机器上使用已安装的工具。导入页上的命令列出了已批准修订版本的准确文件名。

- **Python 3** 使用 `tarfile.USTAR_FORMAT` 创建未压缩的归档。
- **macOS 上的 GNU tar** 使用已安装的 `gtar` 命令。
- **以 `tar` 运行的 GNU tar** 仅适用于 `tar --version` 显示 GNU tar 的环境。

macOS 自带的 tar 即使指定 `--format=ustar`，生成的归档头也无法通过导入校验。每条命令只打包列出的文件。请直接上传生成的 `bundle.tar`，无需压缩，也不要加入其他文件。

## 导入失败时

失败的导入会说明原因。“重新校验”可重试有限次数。“丢弃”会删除已上传的内容。一个工作空间一次只能进行一个导入，所以必须先完成或丢弃失败的导入，才能开始下一个。

## 退役模型

模型页面上的“退役”会把它从列表中移除，并阻止新的部署。正在使用的模型不能退役：请先停止依赖它的内容。文件保留在存储中，历史保留在审计记录中。

## 模型存储

模型保存在安装根目录下的 `data/models`。导入时，请为已上传的模型包和解包后的模型预留空间。表单根据所选模型包和已公布的模型文件大小估算总用量。

模型发布后，服务器会在后台清理模型包和校验产生的临时文件，必要时自动重试。导入历史和已发布的模型文件仍可访问。导入页面显示发布状态。如果临时文件持续占用空间，管理员可以在控制服务日志中查找 `model_import_cleanup_failed` 和导入 ID。[备份](help:getting-started)包含已发布的模型。
