# Owned inference workloads

[manager.go](manager.go) owns approved inference workload state for the explicit Linux amd64/root profile. [execute.go](execute.go), [container.go](container.go) and [docker.go](docker.go) implement bounded operations against a protected Docker socket. The control deployment/node owners still choose and authorize the task.

Model/cache and derived-cache paths validate retained bytes. GPU, memory and preflight helpers admit real resources; network/ownership helpers bind the exact container and network. [verification.go](verification.go) checks actual serving behavior rather than accepting container startup as inference readiness. Registry integration must preserve the same approved image identity.

The private journal binds node/task/command digest, phase, image/network/container IDs, cache-publication intent and verification. Recovery and [remove.go](remove.go) act on that exact ownership. Revoked work, failed model loading, OOM or lost external responses cannot become a new untracked container or broad cleanup. Manager.Close closes owned transport/probe clients without erasing recovery state.

[egress_guard.go](egress_guard.go) keeps owned workload bridges off the network ([ADR 0017](../../../../docs/decisions/0017-workload-egress-guard.md)): the agent's own nftables table rejects every connection a container opens, routed or to the host, and lets only replies to host-opened connections through, so the loopback port publication keeps working. The container's DNS upstream is an unreachable TEST-NET-3 address, because Docker forwards to a host loopback resolver from outside the container's namespace. The network is handed out, and every owned container starts, only after the guard is installed and read back; otherwise the task fails with `INFERENCE_EGRESS_GUARD_UNAVAILABLE`. Offline flags in the image are defence in depth, not the boundary.

[gateway.go](gateway.go) runs the node's model gateway beside the model ([ADR 0052](../../../../docs/decisions/0052-the-model-gateway-runs-beside-the-model.md)). The `gateway` configuration ([gateway_config.go](gateway_config.go)) names the listener, the origin callers use, the image ID loaded from the bundle and a private root. A start generates the credential and key on the node, activates them through the task's lease, accepts only a certificate for that key and origin, writes the files the gateway's account alone reads, and runs one locked-down container per node on the host network, ready once the listener presents the issued certificate. A stop removes the container and the secrets and keeps the report spool. Focused check: `go -C services/agent test ./internal/inference -run Gateway`.

Configuration uses inference.Config and injected [settings](../settings/README.md), with workload roots disjoint from agent identity. Synchronize control/deployments, nodes and models, [agent contracts](../../../../contracts/agent), approved image/model recipes and native Docker/network/GPU tests.

Focused check: `go -C services/agent test ./internal/inference`. The egress guard's real-kernel test is `go test -tags 'docker_integration egress_integration' -run TestActualEgressGuard` as root on Linux with `PROJECT_ONE_DOCKER_SOCKET` and `PROJECT_ONE_EGRESS_PROBE_IMAGE`; `tests/e2e/run-single-node.sh` runs it behind the egress recorder. Docker doubles, native loopback faults, actual OOM and real NVIDIA generation are different evidence profiles; do not promote one to another or weaken platform admission for development-host convenience.
