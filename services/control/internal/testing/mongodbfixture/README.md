# Owned native MongoDB test fixture

`New` reads only the explicit protected `PROJECT_ONE_MONGODB_NATIVE_FIXTURE_FILE`
input generated by the fixed M21 quality entrypoint. It checks binary/seed hashes,
the complete typed policy, declared macOS arm64 or Linux amd64 host and actual `mongod --version`. It creates
an exclusive directory under the admitted evidence root, an ephemeral CA/server
certificate with localhost DNS and loopback IP SANs, a keyfile and a single-member
TLS replica set. No HOME, Keychain, /etc/hosts, system service or shared database
is modified. No certificate verification bypass or arbitrary command hook exists.

The fixture generates independent 3072-bit RSA CA/server keys and writes the
server private key as unencrypted PKCS#1 (`RSA PRIVATE KEY`) in a 0600 PEM file.
The previous EC PKCS#8 fixture failed during the actual macOS 8.0.34 import;
MongoDB's [pinned Darwin implementation](https://github.com/mongodb/mongo/blob/r8.0.34/src/mongo/util/net/ssl_manager_apple.cpp)
uses `SecItemImport`, so parsing the file with Go alone is not native acceptance.
The [MongoDB 8.0 TLS contract](https://www.mongodb.com/docs/v8.0/tutorial/configure-ssl/)
still applies: a certificate/key PEM, explicit CA and matching identity. Pure
controls check key pairing, chain validation, correct DNS/IP SANs, wrong identity
and absent trust; the fixed actual native import remains the compatibility gate.

The temporary localhost bootstrap creates a private SCRAM administrator in memory,
seeds exactly the tracked eight synthetic Extended JSON records, then creates a
source principal with only `find` on the exact collection. Actual write and foreign
collection denial are prerequisites. The production reader receives its ordinary
protected URI/CA source object. `NegativeSource` permits only fixed wrong-password,
wrong-CA and foreign-collection controls at the same actual loopback endpoint.

The child inherits the quality test process group so the outer bounded runner can
stop it on timeout. Startup checks an already exited child before probing, limits
each probe with the typed `query_seconds`, and cancels ongoing bootstrap/probes on
child exit. Its cancellation watchers are joined before cleanup. A closed exit
notification retains the single `Wait` result without consuming/replaying it.
Normal test cleanup disconnects, signals only the still-running owned PID,
waits for a clean exit and records exact log/config/input hashes. Data, credentials
and temp files are removed only after the child has exited; receipts, server log,
version and nonsecret server configuration remain. A forced kill or failed cleanup
fails the test and preserves failure evidence. Interrupted outer runs can retain
owned disposable state as cleanup debt; they never become successful runs.
An observed unsuccessful process exit remains `normal_exit:false` even when its
disposable state is successfully removed. SIGTERM and post-kill join each use the
typed `stop_seconds` bound. A historical interrupted receipt is never rewritten by
a retry or by a later separately recorded manual cleanup.

Coordinator-only lightweight package controls (no MongoDB/SQL server is started):
`go test -race ./internal/testing/mongodbfixture`. `fixture_test.go` covers the
certificate profile, pre-probe exit, in-flight cancellation, query deadline,
exit/readiness race, log bound and stopped-only cleanup preserving diagnostics.
These controls are source until the coordinator records their actual execution.

The fixture is test-only infrastructure. It does not prove multi-node failover,
snapshot expiration, crash recovery, browser support, performance or customer
compatibility. The pinned production Go driver version is unchanged.

The2026-11-03 Linux lane reuses this same fixture on Ubuntu24.04 amd64 with
the pinned Community8.0.34 tarball. See the [M21 increment](../../../../../docs/milestones/m21-mongodb/parallel-20261103.md)
for official archive/binary hashes and the original seed-permission failure.
`enableTestCommands` is fixed true only for this disposable fixture so the
in-memory administrator can inject bounded getMore faults. It does not enter
production configuration or grant source readers command authority. The native
reader test checks concurrent mutation in one snapshot and whole-result discard
on disconnect/deadline/injected SnapshotTooOld. This does not establish natural
history expiry, multi-node failover or the independent M08/HTTP/browser path.
