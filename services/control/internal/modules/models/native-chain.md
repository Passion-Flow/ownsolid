# Native DM approved-model and gateway chain

This is the wave5 owner contract for independently authored native statements. It is source implementation, not a running-engine or hardware qualification. The native schema is supplied by `platform/database/dameng/migrate/contribution_models.go` as `modelsFragment` / `models_v2`; the shared physical-session owner and central schema registration remain indispensable integration dependencies. The baseline alone cannot execute this chain end to end. No engine setting, migration journal, installation profile or source manifest is changed here.

## Delivered first path

1. An authenticated current Admin creates an idempotent approved-base import in the installation Workspace. Current actor/session/epoch, Workspace activity, catalog digest, byte limits, duplicate model and live-import constraints retain their existing owners.
2. Chunk upload preserves the import filesystem lock, exact offset/size/hash checks and SQL chunk identity. Queue, claim, publication, failure and cancellation continue through the retained worker, artifact store, durable rename/readback and audit logic. The native path uses `DBMS_LOCK.REQUEST(id,6,0,FALSE)` on the borrowed pinned session and explicitly releases that lock during bounded cleanup. It does not acquire a second connection to impersonate the session.
3. Publication writes the application-selected immutable model ID, the approved catalog as UTF-8 CLOB text, ready import state and one audit record in the same transaction. Fresh-transaction resolution checks exact import/model/creator/audit identity; retained bytes alone never prove a SQL commit. A statement error returns immediately and is never followed by a query/retry on the poisoned transaction.
4. Approved model reads, scoped lists, tool references, ordinary immutable file transfer/verification and operator inventory reuse the existing manifest and file integrity checks. Native directory reads bypass the optional digest cache, because database JSON reserialization cannot establish the byte fingerprint. The cache remains unchanged for the existing engines.
5. Gateway deployment identity reads the exact tenant/Workspace/node/deployment/GPU/revision relationship, validates the observation in Go and checks the approved model. Native observation revision comparison occurs after strict decoding, avoiding a dialect-dependent JSON integer coercion.
6. Gateway provisioning/revocation, alias publication/disable, target-version recording, API key mint/revoke/list, current admission, canonical outcome report/replay and scoped request readback use native statements. Native recovery challenge/fence/confirmation and restored-authority invalidation preserve existing capacity-release and backend-stop requirements. Transient key revocation is also native.

The HTTP APIs, one-time secret behavior, gateway protocol, artifact format, typed runtime configuration and existing state machines do not change. This slice introduces no environment keys or policy defaults.

## SQL and conversion boundary

Native identifiers use the existing uppercase native schema convention; no PostgreSQL/MySQL text is rewritten. Business values use positional `?` bindings. Native booleans projected from predicates use `CASE ... THEN 1 ELSE 0 END`; stored BIT values retain database/sql bool conversion. UUID CHAR(36) values remain canonical IDs. Hashes remain binary parameters. Validated model manifests, audit metadata, canonical outcomes and fence receipts are explicitly passed as strings for CLOB writes, then decoded and integrity-checked on readback.

The shared ODBC contract requires UTC location, years 1970..9999 and exact microseconds. Native history rejects an unrepresentable cursor with `INVALID_CURSOR`, never truncates it, and expands the descending timestamp/UUID seek into explicit bound comparisons. Native LIMIT is an integer literal only after validation against the existing 1..100 page/lookup bound plus one overflow sentinel; no request text becomes SQL. Native precise-row reference locks use stronger `FOR UPDATE`; callers must provide read-write transactions. Gateway deployment identity locks its exact deployment row, then its exact GPU row, before reading the outer-join projection; other joined authority locks still need target concurrency qualification.

Alias user-lock SELECTs consume `QueryRow().Scan()` and compare the locked user ID; SELECT row counts are never interpreted as mutation counts. Exactly-one native writes check affected rows before proceeding. Multirow restore invalidation and conditional superseding retain their own legitimate cardinality. A native SQL error immediately leaves the complete worker session callback without calling failure bookkeeping on that session; only a recognized file/business failure may enter a new transaction on the still-healthy session. Typed native errors retain their identity over ambient cancellation, and `STORAGE_COMMIT_OUTCOME_UNKNOWN` keeps precedence for every engine. No separate failure-recording session is opened implicitly. An original error is returned without a retry. DTOs and one-time secrets remain private until the existing enclosing transaction succeeds. `ResolveImport`, idempotent re-reads and outcome replay run independently after the original transaction exits.

## Shared integration patch requirements

Only the shared coordinator may implement these dependencies:

- `transaction.FromDameng` must return a real `transaction.SessionStore`. `WithSession(context.Context, func(context.Context, transaction.Store) error)` must retain one physical connection, support multiple successful real transactions without retiring it, restore usable session state between transactions, and dispose of the connection on exit/panic/uncertainty. Statement failure must still poison it. Cleanup uses an independent bounded context; a successful callback cannot hide lock-release or disposal uncertainty, and cleanup cannot replace CommitUnknown. A missing SessionStore deliberately returns `MODEL_STORAGE_UNAVAILABLE` before starting model I/O.
- Preserve the first 31 migration step objects, numbering and hashes. Append native objects through the shared extension API with numbers at least 32; do not register this owner by mutating an old catalog object. Fresh and upgrade schemas must converge after native metadata readback. DDL interruption needs the shared journal reconcile/retry protocol.
- Compose these modules with the same native Identity/Workspaces store. Identity session/ordered user locks, Workspace scope/membership authority, rate admission/license authority and `Nodes.PreparationHistoryWithin` must have actual native implementations. No synthetic authorization, fake node facts or alternate database may substitute in production.
- Register the actual native profile in the owning typed configuration and customer validation runner only when its full declared slice is supported. The current global composition/engine selector is unchanged here. Caller transactions holding native reference locks must not request readOnly.
- Extend the owned repository fixture with a real native Store and native, explicitly authored seed statements; its current PostgreSQL/MySQL `Statement(pg,my)` helper must never relabel either string as native. Required maximum materialized rows include the 1001-row model inventory sentinel. Schema/session profile must enforce UTC and case-sensitive identifiers; JSON_VALUE checks require the qualified native JSON mode.

## Exact schema footprint to append and read back

Use the current owner migrations as semantic contracts, not executable DM SQL. Retain every scope FK, idempotency key, state/check invariant, canonical UUID and immutable identity rule. Native types are CHAR(36) IDs, VARCHAR with matching character limits, BIGINT/INTEGER counters, BIT switches, VARBINARY(32) hashes, TIMESTAMP(6) UTC and bounded checked CLOB JSON. Review Unicode length semantics and OCTET_LENGTH checks against native metadata. The contribution implements active-only uniqueness with generated nullable key columns plus unique constraints. DM exempts a composite unique key only when every key component is NULL, so MODEL_IMPORT_ACTIVE_UK uses ACTIVE_TENANT_ID and ACTIVE_WORKSPACE_ID with the identical predicate STATE NOT IN (ready,cancelled); failed remains active. MODELS_READY_CATALOG_UK uses READY_TENANT_ID, READY_WORKSPACE_ID and READY_CATALOG_DIGEST with STATE=ready for all three. Terminal imports and deleted models project all-NULL keys. Scoped active/ready conflicts still fail; native metadata and runtime enforcement remain qualification gates.

The newly authorized single contribution file supplies 12 native tables, their keys/checks/indexes, immutable record guards and the exact request-to-active-recovery ALTER. It declares `foundation_v1` and `nodes_components_v2` dependencies and resolves their exact unique-key names from the supplied metadata; a missing scoped key produces an invalid fragment, never a weaker FK. The node contribution already supplies INFERENCE_FENCED_AT and the required scoped node/task keys, so no cross-lane ALTER cycle is needed. Central registration and actual DDL execution remain shared-owner work. The only local FK cycle is resolved after both GATEWAY_REQUESTS and GATEWAY_RECOVERIES exist, with full Before/After metadata.

The native schema intentionally accepts approved_base and published/disabled history only. It rejects merged_lora and alias cutover/rollback states until a later contribution supplies their complete guards. This restriction is an explicit first-path implementation boundary, not complete M10 or M29 support. Outcome JSON uses documented native JSON_CONTAINS_PATH plus a JSON_OBJECT_KEYS row-trigger count, because MySQL JSON_LENGTH is not a verified native function. The immutable manifest guard requires DBMS_LOB.COMPARE; package availability/grants and trigger dictionary readback are target gates.

## Verification and remaining boundary

`native_sql_test.go` in models/distribution and `native_gateway_test.go` in deployments provide focused session refusal, single-row mutation/error preservation, dialect fence and cursor/time boundary checks. The alias regression invokes both real entrypoints with SELECT-style Exec counts -1/0, checks exactly one QueryRow/Scan and validates missing/mismatched/error rows. The worker fault tests exercise the full extracted session callback across claim, verification and publication with a poisoning session double, asserting Within counts, no post-poison bookkeeping, original error identity and a known healthy file-error control. These doubles do not qualify SQL or artifact engines. They are test source; this lane is forbidden to run Go builds/tests. `gofmt` parsing and static literal placeholder/argument checks are local evidence only. The coordinator must run the new pure tests, existing PostgreSQL/MySQL regressions, and native integration cases after the shared prerequisites exist.

`native_schema_test.go` parses the actual owned contribution and models its conditional projections under DM's all-NULL exemption. It covers multiple terminal imports within and across Workspaces, every active/terminal state pair (including failed), multiple deleted catalogs, ready catalog scope and negative controls reproducing both old partial-NULL defects. It is a pure source-contract test, not an execution of DDL or metadata introspection. Its synthetic scope labels exercise only key projections, not UUID/FK validation.

Real-DM fixture acceptance must additionally seed valid synthetic scoped rows and assert all of the following through the registered migration/journal path:

- The same tenant retains at least two ready/cancelled import rows in each of two Workspaces, including two terminal rows in the same Workspace. A subsequent active import succeeds in each Workspace, but a second uploading/queued/verifying/failed row in either occupied scope fails MODEL_IMPORT_ACTIVE_UK. Ready/cancelled transitions release that key; failed does not.
- One Workspace retains at least two deleted model versions, including repeated and differing catalog digests; a second Workspace can retain the same deleted catalogs. One ready version per scoped catalog succeeds alongside those rows. A duplicate ready scoped catalog fails MODELS_READY_CATALOG_UK; another catalog or Workspace succeeds. Seed the retired state directly in this isolated fixture because the native retirement API remains outside this slice.
- Dictionary readback confirms all five conditional key columns, their nullable generated expressions, exact key order and enabled enforcement. Repeat conflicting insert/update attempts with real transaction rollback and concurrency; preserve expected constraint errors rather than suppressing them.

Native target acceptance must exercise: import intent replay/fingerprint conflict; duplicate chunks; worker/cancel contention; rollback and unknown commit before/after durable publication; corrupted/symlinked/truncated file readback; actual pinned-session serialization and connection loss; key owner/epoch/membership revocation; stale node/deployment/model observations; concurrent capacity admission; one-time secret redaction after uncertain commit; canonical outcome replay versus changed digest; fence mismatch/supersede/expiry; exact stopped/removed backend proof; no early capacity release; cursor ties/microseconds/actor isolation and restored-authority invalidation. Run with synthetic data only. Preserve failed evidence and remove only the isolated owned database/schema/files after recovery evidence is retained.

Derived model registration, training, modelpreparations, native model retirement, deployment creation/actions, alias cutovers/rollback/target-history listing and monitoring remain unimplemented here. Existing paired helpers reject the unsupported native path instead of selecting another dialect. No NVIDIA inference, native DM driver/server, architecture, browser or real data qualification was performed.
