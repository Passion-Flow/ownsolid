# API keys in the portal

Research behind POR-106, screen S-306 of the [build plan](../product/plan/README.md): a person issues,
rotates and revokes their own keys, sees how to call with one, and reads their own calls. The
administrator's view of the same keys is [gateway keys](gateway-keys.md), S-206.

## What exists

The server already answers everything S-306 needs on the portal's paths
(`/api/v1/sites/{site}/cells/{cell}/workspaces/{workspace}/distribution/...`): keys, their rotation and
revocation, aliases and the request list. A portal session is never an administrator in that module
(`admin()` needs the admin audience), so these paths return and accept only the caller's own keys. No new
backend capability is needed; the page is the portal's view of one that exists.

An alias carries `client_origin`, the HTTPS origin callers use, so the portal can show the endpoint without
the administrator-only gateway list. The Rust gateway serves `POST /v1/chat/completions` and `GET /v1/models`
with a bearer key (`services/gateway/src/routing.rs`).

## How others do it

- **One person, their own keys.** LiteLLM's [internal user role](https://docs.litellm.ai/docs/proxy/self_serve)
  can view, create and delete its own keys; a viewer role can only see them. Open WebUI puts
  [API keys](https://docs.openwebui.com/features/authentication-access/api-keys/) in the person's own account
  settings, and shows a key once.
- **Who may issue.** Both let an administrator decide who may issue personal keys: LiteLLM's
  `key_generation_settings`, Open WebUI's per-group permission. ownsolid lets every member; GW-119 records it.
- **How to keep a key.** OpenAI's [API key guidance](https://help.openai.com/en/articles/5112595) says to read
  the key from a consistently named environment variable, never ship it in code, give it an expiry and rotate
  it. Every sample here reads `OWNSOLID_KEY`.
- **Showing the call.** Microsoft Foundry's [portal](https://learn.microsoft.com/en-us/training/modules/get-started-with-ai-in-azure/5-endpoints)
  generates SDK and REST samples for a deployment. S-306 offers cURL, Python and Node.js.

## Licences

No new dependency in the product. The samples name the `openai` packages for
[Python](https://github.com/openai/openai-python) and [Node.js](https://github.com/openai/openai-node), both
Apache-2.0, which the person installs in their own environment; ownsolid does not ship or call them. The
page uses the portal's React, TanStack and Lucide packages already in the lock file.

## Prototype

The three samples were generated by the code the page uses and run, as written, against a local HTTPS stub
of the gateway's route, with `openai` 2.48.0 (Python, httpx 0.28.1), `openai` 7.53.0 (Node.js 26) and curl.
Each sent `POST /v1/chat/completions` with `Authorization: Bearer <key>` and the alias as the model, and each
printed the stub's answer. This checks the samples and the client libraries, not a model: the installer does
not start the real gateway until GW-114.

An installation usually has a private certificate authority. Without it all three refuse the connection
(`CERTIFICATE_VERIFY_FAILED` and curl's error 60); with `--cacert`, `SSL_CERT_FILE` and `NODE_EXTRA_CA_CERTS`
respectively, all three succeeded. The page says so under the samples, because this is the first failure an
intranet developer meets.

## Decisions

**One implementation of keys.** The list, drawer, call log and dialogs move from the console to
`@ownsolid/shell`, and the API functions take the session's audience, as `listWorkspaces` already does. The
console and the portal differ only in what is the person's to do: the portal has no owner column, and its
"no model" message says an administrator publishes one rather than linking to a console page.

**The reason stays.** The server requires a reason on issue, rotate and revoke for the audit log, and the
portal keeps the field rather than sending invented text.

**Samples read an environment variable, never the secret.** The secret is shown once in the dialog that made
it. Closing that dialog opens the new key's drawer, where the endpoint and samples are, so the next step is
already on screen.

**Python and Node.js use the OpenAI SDK**, which is what integrators use and what an OpenAI-compatible
gateway is for. Rejected: standard-library samples, which need no install but are longer and show nothing a
person would keep. The base URL and model name stand alone for any other client.

**Single-key shortcut.** `K` opens the issue dialog, as in the console.

## Failure modes and tests

Browser flows with a mocked control plane (`web/apps/portal/e2e/keys.spec.ts`) cover: issue with the secret
shown once and the drawer afterwards; a lost answer retried with the same idempotency key; a refused issue;
rotate and revoke; the tiles from the address; the empty, filtered, no-workspace and no-model states; a failed
read and a failed call log, each retried; a key whose model has left the gateway; both languages; the portal
paths being the ones called. Unit tests cover each sample. A live run covers issue, rotate, revoke and reading
calls with a non-administrator's portal session on an installation, and that another person's key is not
found.

## Done when

A person in the portal, in the workspace chosen in the switcher, issues a key for a model the workspace serves
and copies its secret once; sees the endpoint and a working call in cURL, Python and Node.js; rotates it with
an overlap and revokes it by typing its name; reads only that key's calls; and sees no one else's keys. Every
write is audited, enforced on the server, retryable after a failure, and works with no network.

## Per-page CSV and caller CA downloads

The [CSV handoff](gateway-usage-csv-contract.md#web-handoff) and
[CA handoff](gateway-trust-download-contract.md) define the registered
attachment paths and problem responses. Use the generated operations'
path and query types with the existing file transport. It uses the
signed-in browser session, decodes problems and hands successful bytes
to the existing file saver. Save the server's attachment name. A
navigating link would discard the drawer when the server returns a
problem. Do not fetch files on page load.

The call log is an accumulated list of JSON pages. Export one chosen
loaded page with its own opaque cursor, key and limit. The first page
uses no cursor. Show which page the CSV represents, and let the existing
More calls control load the next page before offering its CSV. This
avoids claiming a full export and preserves the production continuation
contract. A cursor rejected by the server shows its problem and reload
action. A failure produces no browser download. Keep download state in
the scoped drawer so switching keys or workspaces cannot reuse a
previous cursor or display its error.

Place the CA action beside the endpoint in the key drawer. The
server owns which aliases have activated trust. Preserve the existing
private-CA setup instructions, including for administrator-managed
gateways. An unavailable bundle explains that the operator provides
the CA for that endpoint. Scope and authorization still come from the
server. The browser saves the public PEM bytes.

Check both attachments in Chromium against the real TLS dispatcher and
PostgreSQL. For CSV, compare the request IDs and digest with the
corresponding key-history pages, including continuation, and exercise
a changed-scope cursor and inaccessible workspace. For CA, compare
the downloaded X.509 fingerprint to the loaded issuer and use the
downloaded bundle to verify the signed gateway endpoint. Check a
refusal without a file. Keep controls in the existing drawer and use
its established error notice and retry behavior. No new dependency,
model or dataset is required.
